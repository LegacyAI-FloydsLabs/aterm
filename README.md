# ATerm

## Or: The Terminal Finally Got Tired Of Pretending Raw Logs Are A Personality

ATerm is a terminal emulator that actually understands what’s happening inside it. Which sounds obvious until you remember most terminals are still glorified green rectangles from the Cold War.

Instead of vomiting infinite text at your AI agent like a haunted receipt printer, ATerm gives structure, state, context, and enough self-awareness to stop your automation stack from wandering into traffic.

It runs in the browser. It exposes an MCP server. Your agents connect to it and suddenly stop behaving like raccoons trapped in a server rack.

The weird part? It works.

## What ATerm Actually Does

Most terminals treat output like sacred prophecy. Every byte matters. Every log line gets preserved forever like archaeologists are gonna excavate your failed npm install in 600 years.

ATerm looked at that situation and said:
“absolutely not.”

So now agents get:

* Semantic terminal state detection (`ready`, `busy`, `waiting_for_input`, `error`, `exited`) with confidence scoring because apparently we had to teach terminals emotional intelligence before certain billion-dollar software stacks figured it out
* Distilled output modes ranging from “show me everything” to “please summarize this catastrophe before I age visibly”
* Output marks so agents can reference failures directly instead of saying things like:

  > “there was an error somewhere near the middle of the screaming”
* Progressive disclosure, meaning tiny local models don’t drown in terminal sludge while larger models get full traces and enough context to become dangerous

Same API. Different intelligence levels. No ritual sacrifice required.

ATerm is basically what happens when you stop treating terminals like sacred relics and start treating them like systems that should cooperate with automation instead of resisting it out of spite.

Which is ironic because spite is usually our primary development framework.

## Quick Start

### Or: Congratulations, You Now Maintain Another Runtime

```bash
# Clone the thing
git clone https://github.com/LegacyAI-FloydsLabs/aterm.git
cd aterm

# Install dependencies and question your choices
bun install
cd ui && bun install && cd ..

# macOS users get a special side quest because of course they do
chmod +x node_modules/node-pty/prebuilds/darwin-arm64/spawn-helper

# Fire it up
npx tsx src/server.ts
```

ATerm prints a URL and token when it starts:

```text
ATerm v0.1.0
Port: 9600
Token: <auto-generated>
URL: http://localhost:9600?token=<token>
```

Open it in your browser.

Create a session.

Run commands.

Watch your terminal suddenly become alarmingly self-aware.

```json
      "args": ["tsx", "/path/to/aterm/src/mcp/server.ts"],

      }
    }
  }
}
```

Cursor works the same way.

Most MCP clients work the same way.

Which honestly feels suspiciously cooperative for modern tooling.

## MCP Tools

| Tool              | What It Does                                                                       |
| ----------------- | ---------------------------------------------------------------------------------- |
| `aterm_list`      | Shows all sessions and whether they’re thriving or collapsing                      |
| `aterm_create`    | Creates a terminal session                                                         |
| `aterm_run`       | Runs commands and returns distilled output                                         |
| `aterm_read`      | Reads terminal output in multiple reduction modes                                  |
| `aterm_start`     | Starts a stopped session                                                           |
| `aterm_stop`      | Stops a running session                                                            |
| `aterm_cancel`    | Sends Ctrl+C directly into the chaos                                               |
| `aterm_answer`    | Responds to prompts like passwords or confirmations                                |
| `aterm_delete`    | Deletes a session permanently                                                      |
| `aterm_note`      | Scratchpad memory for sessions                                                     |
| `aterm_search`    | Searches scrollback across sessions                                                |
| `aterm_history`   | Command history retrieval                                                          |
| `aterm_broadcast` | Sends commands to multiple sessions simultaneously because apparently fear is dead |

## HTTP API

### Or: One Endpoint To Rule Them All

Everything goes through:

```http
POST /api/do
```

Minimal mode:

```json
{"action":"run","session":"build","input":"make all"}
```

Smarter mode:

```json
{"action":"run","session":"build","input":"make all","wait_until":"Build complete","timeout":120}
```

Full galaxy-brain mode:

```json
{
  "action":"run",
  "session":"build",
  "input":"make all",
  "output_mode":"structured",
  "include_marks":true,
  "include_advanced":true
}
```

There are 17 total actions.

Which started as “just a few helpers” and then quietly escalated into an entire orchestration system at approximately 2:13 AM while someone muttered “wouldn’t it be funny if terminals had memory.”

## Security Notes

### Or: Please Do Not Expose Your Entire Machine To The Internet Like A Maniac

ATerm is for local development.

The token grants terminal access to the host machine.

Meaning:
if you expose this thing publicly without additional security layers, you are essentially handing strangers the keys to your digital basement and hoping they behave respectfully.

Historically speaking, that strategy performs poorly.

Use a reverse proxy. Use a VPN. Use common sense. Or at least the modern approximation of it.

## Checkpoints

### Or: No, It’s Not A VM Snapshot, Calm Down

Checkpoint saves:

* Scrollback
* Environment snapshots
* Working directory
* Notes
* Command history
* Session config

Checkpoint does *not* save:

* Running process state
* Containers
* Databases
* Open network connections
* Whatever cursed thing your dev server was doing internally

Restore recreates the PTY and replays the session visually.

Think “workspace memory,” not “time machine.”
